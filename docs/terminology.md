# 용어 정의 (Terminology)

이 문서는 **Threat Insight** 프로젝트 전반에서 사용되는 보안 도메인 용어를 정의합니다.
코드, 데이터베이스 스키마, API, 문서 전반에서 동일한 의미로 용어를 사용하기 위한 기준 문서입니다.

---

## 1. 핵심 개념(Core Concepts)

| 용어                   | 정의                                                                | 비고                   |
| ---------------------- | ------------------------------------------------------------------- | ---------------------- |
| Threat (위협)          | 시스템, 서비스, 데이터에 영향을 줄 수 있는 모든 보안 관련 위험 요소 | 가장 상위 개념         |
| Vulnerability (취약점) | 공격자가 악용할 수 있는 **구체적인 소프트웨어 결함**                | CVE와 매핑             |
| Weakness (약점)        | 취약점이 발생하는 **구조적 또는 설계상의 공통 원인**                | CWE와 매핑             |
| Severity (심각도)      | 위협 또는 취약점의 위험 수준을 정성적으로 표현한 값                 | LOW ~ CRITICAL         |
| Score (점수)           | 위험도를 수치로 표현한 값                                           | 주로 CVSS 점수         |
| Explanation (설명)     | 비전문가도 이해할 수 있도록 풀어서 설명한 내용                      | 규칙 기반 또는 AI 생성 |

---

## 2. 위협 데이터 분류

| 유형          | 설명                                                  |
| ------------- | ----------------------------------------------------- |
| VULNERABILITY | 개별 취약점 데이터 (예: CVE 항목)                     |
| WEAKNESS      | 취약점의 유형 또는 패턴 (예: CWE 항목)                |
| INCIDENT      | 실제 발생한 보안 사고 또는 침해 사례 (향후 확장 대상) |
| INDICATOR     | 침해 지표(IOC) 또는 위협 신호 데이터 (향후 확장 대상) |

---

## 3. 외부 표준과의 매핑

| 외부 표준 | 내부 용어              |
| --------- | ---------------------- |
| CVE       | Vulnerability (취약점) |
| CWE       | Weakness (약점)        |
| CVSS      | Score / Severity       |

---

## 4. 대상 사용자 정의

| 대상      | 설명                         |
| --------- | ---------------------------- |
| GENERAL   | 보안 지식이 없는 일반 사용자 |
| DEVELOPER | 소프트웨어 개발자            |
| SECURITY  | 보안 엔지니어 또는 분석가    |

---

## 5. 약어 사용 규칙

- **CVE**, **CWE**, **CVSS**와 같은 표준 보안 약어는 사용을 허용합니다.
- 프로젝트 내부에서 임의로 만든 약어 사용은 지양합니다.
- 데이터베이스 컬럼명에는 업계 표준이 아닌 약어를 사용하지 않습니다.

---

## 6. 금지 용어 및 권장 용어

### 금지 용어

- Issue
- Bug
- Risk (의미가 모호한 경우)

### 권장 용어

- Vulnerability (취약점)
- Weakness (약점)
- Threat (위협)

---

## 7. 변경 정책

- 도메인 개념 또는 명칭이 변경될 경우, 반드시 이 문서를 먼저 수정합니다.
- 코드, 데이터베이스, API 네이밍은 본 문서에 정의된 용어를 기준으로 합니다.
